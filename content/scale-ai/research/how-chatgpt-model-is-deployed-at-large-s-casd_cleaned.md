**Functional Requirements and Architecture Overview**

We are building a horizontally scalable LLM-based architecture that supports:

- Massive concurrency across thousands of pipelines, each capable of - handling millions of user queries
- Support for custom documents via an intermediate RAG system
- Context preservation for chat-based experiences
- Cost-efficiency and throughput optimization using batching, speculative decoding, and caching mechanisms

![Screenshot 2025-05-28 222500.png](https://assets.leetcode.com/users/images/46155c1d-4fca-4c2e-8640-580c589fee85_1748528849.009871.png)

**Design Components:**

- Blob Storage (e.g., S3): Stores custom documents from the client
- Embedding Generator: Runs asynchronously & Parses documents and generates vector embeddings. Stores them in a Vector DB

**RAG System (Intermediate Layer):** When a client query is received:

- It queries the Vector DB using the query's embedding. Retrieves relevant documents based on cosine similarity. Supplies those as context to the main LLM. Optionally fetches live web data (via crawler) for real-time information injection

This allows enterprises to train or semi-finetune models on their private data without retraining the entire model, providing both flexibility and scalability.

**Context Preservation (For Stateful Chat)**

For generic, stateless queries (e.g., a ChatGPT-like experience), we maintain session continuity using Context Cache:

- Stored in the Query Server
- Uses a sliding window mechanism to retain the most recent tokens up to the LLM's max token limit
- Maintains user sessions, associating each query with its context history

This enables natural back-and-forth conversation without requiring clients to manage state

**Speculative Decoding with Smaller Models**

Incoming queries are first routed to a smaller, lightweight model and Generates multiple possible continuations or answers (n-best list).These are used as speculative context options for the large model.The large model then:

-Picks the best option

-Or refines it to produce a better final answer

Benefit: Reduces compute usage on expensive LLMs by filtering through cheap first-pass guesses.

**KV (Key-Value) Caching on GPU**

During inference, self-attention layers calculate new outputs based on previous tokens. We cache these intermediate attention values (called KV Cache) on the GPU memory

Example:

Prompt: “Tell me the features of Apple”

First few tokens help the model understand context (Apple product vs fruit)

In the third token prediction, cached KV values help focus attention on “Apple products” rather than “fruit”
