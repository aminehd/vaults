# Google L3 Interview Questions (C++, Graphs, API Optimization)

## Questions

### C++ · Easy
What is the performance implication of initializing an empty `std::vector` and adding many elements one by one via `push_back`? What is a more optimal way?

**Approach:** Pushing to an empty vector repeatedly can cause multiple reallocations and copies of the underlying array as it grows, which is inefficient. A more optimal way is to use `vector::reserve()` if the number of elements is known or can be estimated, or `vector::resize()` if you want to default-construct the elements upfront.

### Graphs · Medium
Given a list of flights (source, destination, departure time, arrival time), find a valid itinerary from a start to a destination airport. A follow-up asked whether a `visited` set is necessary in a time-dependent graph.

**Approach:** Model the airports and flights as a directed, time-dependent graph. A traversal like DFS or BFS can find a path. A `visited` set is still necessary to prevent cycles, as you could have a flight path `A -> B -> A` where the times allow for the cycle. The visited state might need to include time to be fully correct, e.g., `visited[airport][time]`.

### API Optimization · Hard
An `n x n` grid contains `n-1` rooks, each in a unique row and column. You are given an API `int countRooks(r1, c1, r2, c2)` that counts rooks in a subgrid. Find the empty row and column using the minimum number of API calls.

**Approach:** A linear scan (`2n` calls) can find the empty row/column by checking each one individually. The optimal solution uses binary search. To find the empty row, you can query `countRooks(0, 0, mid, n-1)`. If the count is `mid + 1`, the empty row is in the upper half; if it's `mid`, the empty row is in the lower half. This finds the row in O(log n) calls. Repeat for the column.
